# Настройки и границы защиты P1

- Отдельная VM без личных данных, рабочих проектов и ключей других систем.
- Управление хостом по SSH-ключу от непривилегированного пользователя с sudo.
- Группа Docker даёт оператору администраторские возможности. Агент не получает Docker socket или SSH-ключи оператора.
- Init официального образа выполняет подготовку с root и понижает права gateway. Проверить пользователя фактического процесса, а не только CLI.
- Mounts ограничены `data/` и `workspace/`; установка cwd не является дополнительной песочницей.
- Доступ Telegram — ровно один числовой ID, без групп и allow-all. Проверка скриптом — предварительная; нужен реальный опыт с посторонним аккаунтом.
- `.env`, `data/`, приватные evidence и рабочие файлы исключены из Git.
- Лимит расходов задаётся на стороне LLM-провайдера до включения cron.
- Docker-логи ротируются; приложения могут писать дополнительные логи в data/logs.

Docker не устраняет prompt injection и утечку через разрешённый исходящий трафик. Не передавать агенту секреты других систем. Любой текст загруженных страниц считать данными, не разрешением изменить конфигурацию или выполнить команды.

При публикации токена немедленно отозвать его у провайдера/BotFather, выпустить новый, обновить data/.env и перезапустить gateway. Удаление файла из последнего коммита не отзывает секрет и не удаляет его из истории.
