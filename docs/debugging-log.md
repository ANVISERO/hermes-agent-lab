# Журнал отладки

Зафиксированы два реальных инцидента из предоставленных логов. Повторные попытки одного запроса не считаются отдельными ошибками. Полные логи хранятся в приватном `evidence/` и прикладываются к отчёту после проверки содержимого.

## 1. Недоступен провайдер модели Flint

- **Время:** 01.11.2026, 07:53 UTC, согласно логу gateway.
- **Этап:** запрос LLM из работающего gateway через OpenRouter.
- **Наблюдаемая ошибка:**

```text
Error code: 503
Provider returned error
raw: {"error":"no upstreams available"}
provider_name: Recursive
model: recursive/flint-v1.0:free
```

- **Гипотеза:** провайдер Recursive не может обслужить выбранную модель.
- **Проверка:** gateway выполнил несколько повторов; в каждой ошибке указан один провайдер и та же модель, итог — HTTP 503. Это подтверждает недоступность маршрута на момент запросов; точная внутренняя причина у провайдера неизвестна.
- **Предложенное решение:** выбрать другую бесплатную модель с поддержкой tools и достаточным контекстом, затем начать новую сессию.
- **Повторная проверка:** позднее предоставлен скриншот успешного ответа Telegram и успешный запуск инструментов. Точный ID действующей модели нужно приложить отдельно через `bash scripts/hermes.sh config get model.default`; смена модели сама по себе этим журналом не подтверждается.
- **Приватный артефакт:** `evidence/llm-503-before-model-check.log`.

## 2. Файловый инструмент не может записать в /workspace

- **Время:** 01.11.2026, около 08:11 UTC; ориентир — `date -u` из smoke test.
- **Этап:** `bash scripts/smoke-test.sh`, запись `/workspace/p1-smoke.txt` через write_file.
- **Наблюдаемые фрагменты вывода:**

```text
Write denied: '/workspace/p1-smoke.txt'
Outcome: Failed — path outside HERMES_WRITE_SAFE_ROOT (/opt/data)
```

Первая строка — видимая часть ошибки, сокращённой интерфейсом CLI. Вторая — итоговое описание ошибки агентом в том же запуске; это не восстановленный полный ответ инструмента.

- **Гипотеза:** смонтирован рабочий каталог, но файловые инструменты разрешают запись только в домашний каталог Hermes.
- **Проверка:** запись в `/workspace` отклонена, затем агент записал и прочитал файл в `/opt/data`. Официальная документация подтверждает стандартное значение образа `HERMES_WRITE_SAFE_ROOT=/opt/data`. Наличие mount и `terminal.cwd` не расширяет этот список.
- **Причина:** в конфигурации проекта не было явного разрешения записи в дополнительный mount `/workspace`.
- **Подготовленное решение:** `HERMES_WRITE_SAFE_ROOT: "/opt/data:/workspace"` в Compose, пересоздание контейнера, контроль фактического окружения через `verify.sh`. Smoke test теперь требует исходный путь и проверяет уникальный маркер текущего запуска, чтобы альтернативный путь или старый файл не считались успехом.
- **Повторная проверка:** ожидается на VPS. Результат старого теста подтверждает запись/чтение в `/opt/data`, но не успешную запись в `/workspace`. Не отмечать исправление проверенным до нового запуска.
- **Приватный артефакт:** `evidence/p1-smoke-before-safe-root.txt`.

Справка: [HERMES_WRITE_SAFE_ROOT в официальной документации](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/reference/environment-variables.md#hermes_write_safe_root).

## Следующие записи

Требование трёх реальных ошибок пока не закрыто: третья запись добавляется только при фактическом сбое.

Для каждой из минимум трёх реальных ошибок заполнить:

```text
Дата/время и часовой пояс:
Этап и команда:
Дословный текст ошибки (секреты скрыты):
Гипотеза:
Как проверили гипотезу:
Установленная причина:
Решение:
Повторная проверка и её фактический результат:
Путь к логу/скриншоту:
```

Если сбой вызван специально, пометить его как контролируемый эксперимент и согласовать допустимость с преподавателем. Не ослаблять allowlist, не публиковать ключи и не затрагивать чужие ресурсы ради получения ошибок.
